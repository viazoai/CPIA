# 클립 02 — 자동화 모듈 · 3분 (180초)

> **목적:** 작업일보가 들어오는 순간부터 통합 작업일보가 나오기까지의 **AI 자동 처리 사이클** 전체를 보여준다.
> 핵심 메시지: *"담당자 1~3명이 매일 2~3시간 매달리던 7단계 수작업이, 사람은 8%만 검토하는 5분짜리 흐름으로 바뀐다."*
> **화면:** `/home` → `/tasks` (02) → `/review` (03) → `/export` (04)
> **분할:** 홈 30s · Task 60s · Review 50s · Export 40s

---

## 전체 흐름

```
[홈]  오늘의 현장 한눈에  ──30s──►  무엇이 들어오는지(작업일보·미제출) 인지
   │
[Task]  작업일보 업로드 → 7-Agent 파이프라인 자동 실행 ──60s──►  Collector~Atomizer 자동, Mapper에서 멈춤(H-i-L)
   │
[Review]  AI가 92% 매핑 / 사람은 8%만 검토·확정 ──50s──►  "모두 확정" → 파이프라인 재개
   │
[Export]  업체별 일보 → 통합 작업일보 1장 → Excel 출력 ──40s──►  보고서가 자동으로 완성
```

> 발표 전략 v04 *Process* 슬라이드(수작업 7단계 → 7-Agent)와 1:1 대응. 이 클립이 그 슬라이드의 "실제 동작 증거".

---

## 1) 홈 — 오늘의 현장 (0:00–0:30)

| 시간 | 화면 / 조작 | 화면에 보이는 것 | 나레이션 |
|------|-------------|------------------|----------|
| 0:00–0:08 | `/home` 상단 헤더 정지 | 현장 항공사진 + **M15X Ph-3 IBL**, 2025.09.25, 날씨, 인삿말 | "현장 운영 홈입니다. 오늘 날짜와 현장 상황을 띄워 두고 하루를 시작합니다." |
| 0:08–0:18 | 좌측 **생산성 현황 / 제출 현황** 으로 이동 | KPI: **생산성(목표 대비)**, **최적화 공사기간(일)** · 제출 **n/n 업체**, **미제출** 칩(빨강) | "좌측에는 오늘의 생산성과, 일보를 제출한 업체·미제출 업체가 한눈에 정리됩니다. 누가 아직 안 냈는지 바로 보입니다." |
| 0:18–0:30 | 우측 **오늘 작업내용** 테이블 + **AI 작업 요약(FAB/CUB)** 강조 | 공종·업체·작업내용·인원·장비 행 / 상단 **AI 작업 요약** 2줄 | "우측은 업체별 작업 내용입니다. 맨 위 'AI 작업 요약'은, 수십 개 일보를 AI가 동(棟)별로 한 문장씩 요약해 둔 겁니다. 그럼 이 데이터가 어떻게 만들어지는지 보겠습니다." |

**전환:** 상단 네비 **`Agent Tasks`(02)** 클릭 → `/tasks`

## 2) Task — 7-Agent 자동 처리 (0:30–1:30)

| 시간 | 화면 / 조작 | 화면에 보이는 것 | 나레이션 |
|------|-------------|------------------|----------|
| 0:30–0:38 | `/tasks` 진입, 3단 레이아웃 정지 | 헤더 *"작업일보 처리 현황"* · 좌(일자별 Daily Tasks)·중(Agent Workflow)·우(단계별 건 목록) | "작업일보 처리 화면입니다. 매일 이메일·메신저로 들어오는 업체별 일보를, 7개의 Agent가 순서대로 처리합니다." |
| 0:38–0:46 | 우상단 **`작업일보 업로드`** 클릭 → 업로드 다이얼로그 → 파일 드롭 → 시작 | 업로드 모달, 파일명 `..._20250925` | "오늘 들어온 업체 일보를 그대로 올려보겠습니다. 파일을 넣는 순간—" |
| 0:46–1:05 | 업로드 직후 자동 시작 — 좌측 목록 최상단에 오늘 카드 prepend, 중앙 **Agent Workflow** 단계가 차례로 점등 | **Collector → Parser → Mapper → Atomizer → Exporter → Forecaster → Optimizer** 순서, 진행도 채워짐 | "파이프라인이 자동으로 돕니다. Collector가 파일을 읽고, Parser가 비정형 텍스트를 구조화하고, Atomizer가 현장 지식 DB에 적재합니다. 사람 손은 아직 한 번도 닿지 않았습니다." |
| 1:05–1:18 | **Mapper** 단계에서 진행 정지(`waiting_hil`) — 카드 상태 *검토 대기* | Mapper 단계 점등 + 멈춤, 우측 목록에 매핑 결과 행 노출 | "그런데 Mapper에서 멈춥니다. 작업 내용을 공정표(WBS)에 연결하는 단계인데—" |
| 1:18–1:30 | 우측 단계별 건 목록 천천히 스크롤, 확신도(%) 칼럼 강조 | 매핑 항목별 **확신도** — 높은 건 자동, 낮은 건 표시 | "AI가 평균 약 92% 정확도로 자동 매핑하지만, **확신이 낮은 건만큼은 사람에게 넘깁니다.** 100% AI가 아니라, 모르는 건 사람에게 묻는 구조—이게 신뢰의 핵심입니다. 그 검토 화면으로 가보겠습니다." |

**전환:** 상단 네비 **`Human Review`(03)** 클릭 → `/review`

> **촬영 메모:** 업로드 후 시뮬레이션은 250ms tick으로 단계가 자동 전환. Mapper에서 `hil_paused` 로 멈추는 연출이 포인트 → 멈춘 프레임을 2초 이상 확보. 실제 DB run이 붙어 있으면 polling 으로 진짜 진행도가 우선 표시됨(둘 다 자연스러움).

## 3) Review — 사람은 8%만 검토 (1:30–2:20)

| 시간 | 화면 / 조작 | 화면에 보이는 것 | 나레이션 |
|------|-------------|------------------|----------|
| 1:30–1:40 | `/review` 진입 정지 | 헤더 *"WBS-작업 물량 관계 검토"* · 좌(WBS 트리: 건물 > 공종 > Work Package, 전개됨) · 우(작업물량 카드) · 우상단 토글 **신규 검토 필요(ON)** | "검토 화면입니다. 좌측은 현장의 공정표 WBS, 우측은 오늘 들어온 작업 물량입니다. '신규 검토 필요'가 켜져 있어, **확신도가 낮아 사람 확인이 필요한 건만** 보입니다." |
| 1:40–1:55 | 카드 하나 클릭 → 좌측 WBS 트리의 매핑 대상 노드로 **연결선**이 그어지고 자동 스크롤 | 카드↔WBS 노드 연결선(mint/sun), 확신도·경로 표시 | "한 건을 누르면, AI가 어디에 연결했는지 선으로 보여줍니다. 맞으면 그대로 두고—" |
| 1:55–2:08 | 한 카드의 매핑을 드롭다운/드래그로 수정(remap) → 확신도 1.0 갱신 | 매핑 경로 변경, 카드 상태 갱신 | "틀렸다면 올바른 공종으로 끌어다 놓으면 됩니다. 사람이 고친 건 그대로 학습 데이터가 됩니다." |
| 2:08–2:20 | 하단 **`모두 확정`** 클릭 → 토글이 등록 모드로 전환 + *"N건 확정 완료"* 알림 | 확정 알림, `/api/hil/resume` 호출 → 파이프라인 재개 | "검토가 끝나면 '모두 확정'. 이 순간 멈춰 있던 파이프라인이 다시 돌기 시작합니다. 사람이 만진 건 전체의 8%뿐입니다." |

**전환:** 상단 네비 **`Export`(04)** 클릭 → `/export`

> **촬영 메모:** 토글 라벨은 **"신규 검토 필요"**, 기본 ON. WBS 트리는 최하위까지 펼쳐진 상태가 기본. `모두 확정` 후 등록 모드로 자동 전환되며 알림이 잠깐 뜨므로 그 프레임 확보.

## 전체 촬영 메모
- 네비게이션 전환은 **상단 네비 클릭**으로(주소창 직접 입력 X) — 같은 앱 안의 흐름임을 보여줄 것.
- Task→Review→Export 는 데이터상 같은 날(2025-09-25) 흐름이어야 자연스러움. 좌측 일자 리스트에서 항상 **9/25** 가 선택돼 있는지 확인.
- 5535 production 빌드 권장(파이프라인 애니메이션·연결선 SVG 안정). 수정 직후라면 `make build` 후 `docker logs cpia-web` 로 `✓ Ready` 확인하고 녹화.

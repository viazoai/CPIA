BG · Background

과제의 본질 —
현장의 일을 재정립한다

이 과제는 단순히 현장의 보고 업무를 줄이는 자동화가 아닙니다. 현장 엔지니어가 수행하는 업무 중 AI로 대체 가능한 Middle Office 레이어를 제거하고, 그 인력을 Front Office 본연의 역할(공정 판단·발주처 협상·리스크 실행)로 재배치함으로써 조직의 일하는 방식을 구조적으로 전환합니다.

연결점 ①
Atomizer → Vector DB 자동 구축
매일 작업 기록이 현장 지식으로 쌓임. 별도 구축 없이 파이프라인 운영만으로 Vector DB가 자동 성장합니다.
연결점 ②
Forecaster: 과거 유사 상황 검색
절대 기준(품셈) 대신 현장 고유 패턴으로 판단. 오늘 생산성이 이 현장·이 업체·이 조건에서 정상인지 비교합니다.
연결점 ③
Optimizer: RAG 기반 만회 조언
유사 저하 사례에서 효과 있었던 방법 제시. 추상적 조언이 아닌 현장 실적 기반 근거 있는 만회 방법입니다.
03 · 차별점

현장이 스스로 기준을 만든다

기존 생산성 관리는 외부 표준(품셈)을 기준으로 현장을 평가했습니다. CPIA는 현장 실적 이력이 곧 기준이 됩니다.

CPIA v7 핵심 전환
외부 기준(품셈)으로 평가 → 이 현장, 이 업체, 이 조건에서 과거 대비 오늘이 정상인가로 판단
▼ 기존 방식 — 품셈 기반

데이터 선순환 구조
Stage 1 — Atomizer
매일 자동 누적
작업일보 처리 시 Vector DB 자동 갱신. 현장 고유 패턴이 매일 축적됩니다. 별도 작업 없이 파이프라인 운영만으로 지식 DB가 성장합니다.
Stage 2 — Forecaster
맥락 기반 진단
오늘 생산성을 과거 유사 상황과 비교. 날씨·여건을 반영한 판단. 데이터가 쌓일수록 유사 사례 검색 범위가 넓어져 판단 정확도가 향상됩니다.
Stage 3 — Optimizer
근거 있는 조언
실제 효과가 있었던 유사 사례 기반 만회 방법 제시. 선순환: 조언 실행 → 결과 기록 → Vector DB 반영 → 다음 조언 품질 향상.

3단계 AI 처리 흐름 (데이터 → 인사이트)
Stage 1 — Mapper Agent
Semantic Mapping
비정형 작업일보 텍스트를 LLM이 문맥 해석 → 공정표·실행내역 항목에 자동 분류·할당. 현재 담당자가 수작업으로 가장 많은 시간을 소모하는 단계.
Stage 2 — Atomizer
Vector DB 적재
매일 작업 기록을 ChromaDB에 임베딩. 현장 지식 DB 자동 갱신. 날씨·조건 메타데이터 포함하여 유사 상황 검색 정확도를 높입니다.
Stage 3 — Forecaster + Optimizer
Forecasting + Optimization
Vector RAG 기반 현장 고유 패턴 판단. 과거 유사 상황 검색 → 진단 → 만회 조언. 데이터가 쌓일수록 판단 정확도가 향상됩니다.
v7 핵심 변경: 외부 지식(품셈·표준단가)에 의존하지 않습니다. Atomizer가 매일 작업일보를 처리하면서 자동으로 현장 지식 DB를 구축합니다. 초기(데이터 부족)에는 WBS 계획값을 fallback으로 사용, 누적 실적이 쌓이면 자동 전환됩니다.
보안: 실행내역·작업일보 대외비 등급 → 전사 AI 인프라(사내 승인 환경) 사용 전제. 고객 개인정보 미포함으로 규제 리스크 없음.

08 · LangGraph

기술 구현 — LangGraph 기반
Multi-Agent 아키텍처

CPIA는 7개 전문 Agent가 상태를 공유하며 협력하는 구조입니다. Human-in-the-Loop가 2곳에 존재합니다.

LangChain vs LangGraph — 왜 LangGraph인가
비교 항목 LangChain LangGraph ✓ 채택
실행 구조 선형 체인 — A→B→C 순차 실행. 분기·반복 불가. ✓ StateGraph — 조건 분기·사이클·병렬 실행 모두 지원.
Human-in-the-Loop ✗ 네이티브 미지원. 체인 중단 후 상태 보존 불가. ✓ interrupt() — 파이프라인 일시정지, 상태 저장, 승인 후 재개.
Multi-Agent 단일 AgentExecutor 기반. Agent 간 상태 공유 어려움. ✓ CPIAState 공유로 7개 Agent가 동일 컨텍스트 접근.
조건부 라우팅 if/else 직접 구현. 파이프라인 구조 외부에 존재. ✓ add_conditional_edges() — 신뢰도 낮은 매핑 자동 분기.
장애 복원 체인 실패 시 처음부터 재실행. ✓ PostgresSaver — 단계별 상태 저장, 장애 지점부터 재개.
적합 Use Case 단일 Agent RAG, 문서 Q&A, 단순 Tool 호출. ✓ Human 개입 포함 복잡한 Multi-Agent 오케스트레이션.

CPIAState — 공유 상태 및 H-i-L 구현
# 모든 Agent가 공유하는 단일 상태 객체 from langgraph.graph import StateGraph, START, END from typing import TypedDict, Literal from langgraph.checkpoint.postgres import PostgresSaver class CPIAState(TypedDict): date: str # 처리 기준일 raw_reports: list[dict] # Collector: BP 원본 작업일보 structured_data: list[dict] # Parser: WBS 구조화 JSON mapped_activities: list[dict] # Mapper: 공정표 매핑 완료 mapping_approved: bool # H-i-L 1: PM 매핑 승인 여부 vector_db_records: list[dict] # Atomizer: Vector DB 적재 레코드 daily_report: str # Reporter: 생성된 보고서 forecast: dict # Forecaster: 생산성 진단 결과 selected_trades: list[str] # H-i-L 2: PM 선택 공종 목록 optimizer_advice: dict # Optimizer: 만회 조언 # H-i-L 1: Mapper 이후 매핑 검증 def mapping_review_node(state: CPIAState): from langgraph.types import interrupt uncertain = [a for a in state["mapped_activities"] if a.get("confidence", 1.0) < 0.8] interrupt({"uncertain_mappings": uncertain, "action": "매핑 검증 요청"}) return {"mapping_approved": True} # H-i-L 2: Forecaster 이후 조언 대상 공종 선택 def trade_selection_node(state: CPIAState): from langgraph.types import interrupt risk_trades = state["forecast"].get("risk_trades", []) interrupt({"risk_trades": risk_trades, "action": "조언 의뢰 공종 선택"}) return {}
핵심 설계 원칙
원칙 ①
Human-in-the-Loop 2지점
Mapper 이후 매핑 검증(10분) + Forecaster 이후 의뢰 공종 선택(5분). 합산 15분 개입으로 AI 판단을 PM이 통제합니다.
원칙 ②
Vector RAG 자기학습
H-i-L 1에서 PM이 수정한 매핑은 corrections.json에 누적됩니다. 같은 내용이 반복 등장하면 Mapper가 자동 확정 처리 — 반복할수록 개입이 줄어드는 구조.
원칙 ③
모델 최적화 배치
속도·비용 균형이 중요한 Parser·Mapper·Reporter는 Claude Sonnet 4.6, 복잡한 맥락 추론이 필요한 Forecaster·Optimizer는 Claude Opus 4.7.

# CPIA 확장 아이디어 — 현장 기억(지식화) & 업체 인텔리전스

> 작성: 2026-06-02 · 성격: **아이디어 검토안** (개발 설계 아님)
> 전제: CPIA 파이프라인이 매일 쌓는 데이터 자산을 *읽어서* 부가가치를 만드는 확장. 파이프라인 그래프는 건드리지 않는다.

---

## 0. 출발점 — CPIA가 매일 쌓고 있는 데이터 자산

두 아이디어 모두 "이미 쌓이는 것"을 재료로 한다. 새로 만들 데이터는 없다.

| 자산 | 저장소 | 성격 | grain |
|------|--------|------|-------|
| `daily_activities` | ChromaDB | 작업일보 1행 = 1 doc, `work_content` 임베딩 (의미 검색 가능) | Activity 단위 |
| `forecasts` | PostgreSQL | 공종별 생산성 진단 — 생산성·조건·공기갭·회복확률 | (업체 × 공종) × 일 |
| `optimizer_advice` | PostgreSQL | degradation→recovery 패턴 + 조언 | (업체 × 공종) |
| `activity_master` | PostgreSQL | Plan 기준값 (계획 MH/물량/공기) | WBS Activity |

> **핵심:** 이 자산들은 *시간이 갈수록 두꺼워진다.* 두 아이디어의 가치도 누적량에 비례해 커진다 — "쓸수록 쓸모 있어지는" 구조.

### 두 아이디어는 같은 엔진의 두 얼굴

- **A (현장 기억)** = 쌓인 기록을 **유사도로 꺼내서 종합** (Chroma 검색 → PG 조인 → 요약)
- **B (업체 인텔리전스)** = 쌓인 기록을 **업체 기준으로 모아서 집계** (PG group by 업체 → 통계)

둘 다 *읽기 전용 분석 레이어*라 기존 시연 흐름을 깨지 않고 "그리고 이런 것도 됩니다"로 얹을 수 있다.

## A. 현장 기억 — 지식화 / 검색

### 한 줄 정의
> 매일 제출되고 사라지던 작업일보를, **검색되는 현장 기억**으로 바꾼다. "비 올 때 철근 작업 어떻게 했었지?"에 과거 실제 사례 + 그날 생산성 + 당시 조언으로 답한다.

### 구성 (하이브리드: 칩으로 시작 → 채팅으로 심화)
1. **조건 칩 패널** — 자주 쓰는 facet을 칩으로: `조건`(우천·장비대기·병행작업…) × `공종`(건축·설비·전기…) × `업체`. 빈 채팅창 부담 없이 클릭으로 좁힘.
2. **사례 카드 리스트** — 칩 조합에 맞는 과거 기록을 카드로. **카드 1장 = 작업기록 + 그날 생산성 + 당시 조언**, 그리고 *언제·어느 현장·어느 공종*인지 출처 명시.
3. **"이어서 물어보기" 채팅** — 현재 칩 맥락을 들고 자연어 질문 → 위 카드들을 **근거로 인용해** 답변.

### 활용 데이터
| 무엇을 | 어디서 | 어떻게 |
|--------|--------|--------|
| 유사 작업 검색 | Chroma `daily_activities` | `work_content` 의미검색 + 메타필터(conditions·l5_disc·company) |
| 그날 생산성·조건 | PG `forecasts` | (date, company, l6_main) 조인 |
| 당시 조언 | PG `optimizer_advice` | (company, l6_main) 조인 |
| 종합 답변 | Azure OpenAI gpt-5.1 | 검색된 카드만 근거로 요약 (카드 밖 단정 금지) |

### 산출 인사이트
- 조건별 과거 대응 사례집 ("우천 시 콘크리트 타설 사례 7건")
- 신규 PM 온보딩 / **인수인계 자동화** — 사람이 나가도 의사결정 맥락이 검색으로 승계
- "그때 그 상황 어떻게 풀었지?"를 즉답

### 구현 가능 범위 (정직한 단계 구분)
| 단계 | 가능 여부 | 비고 |
|------|-----------|------|
| **칩 필터 + 사례 카드** | ✅ 지금 바로 | `daily_activities` 메타필터 + PG 조인만으로 됨 |
| **자연어 채팅 종합** | ✅ 지금 바로 | 기존 Azure OpenAI 재사용. 환각 차단(인용 강제)이 품질 관건 |
| **현장 간 지식 전이** | ⚠️ 데이터 누적 후 | PoC는 실현장 1개 → 단일 현장 내에선 즉시, 다현장 전이는 누적 필요 |

### 한계 / 리스크
- **환각이 가장 큰 위험** — 건설에서 잘못된 단정은 사고로 이어짐. 답변은 *검색된 카드 범위 안*에서만, 사례 없으면 "유사 사례 없음"으로 정직하게.
- 단일 현장 PoC에선 "기억의 폭"이 얕음 → 가치는 누적과 함께 증가.

## A+. 확장 — 현장 Wiki (검색 → 지식화)

> A(현장 기억)를 한 단계 끌어올리면 **현장 Wiki** 가 된다. "물어보면 꺼내주는 검색"에서 "주제별로 정제·축적되어 스스로 자라는 지식"으로의 질적 도약.

### 검색 → 위키, 무엇이 달라지나
| | 현장 기억 (검색) | 현장 Wiki (지식화) |
|---|---|---|
| 단위 | 원본 기록을 그때그때 꺼냄 | 주제별로 **정제·축적된 페이지** |
| 성격 | 반응형 (물어야 답) | **상시 존재 + 자가 성장** (매일 갱신) |
| 내용 | "이런 기록이 있었다" | "여기선 이렇게 한다 / 이래서 이렇게 됐다" |
| 신뢰 | 원본이라 그대로 | 사람이 핀·정정으로 **큐레이션** |

핵심 도약 4가지:
1. **자동 생성 페이지** — 공종·조건·구역·업체·장비별로 누적 경험을 요약한 페이지가 *저절로* 생성
2. **자가 성장** — 오늘 작업일보 + 진단(`forecasts`) + 조언(`optimizer_advice`)이 관련 페이지에 매일 합류
3. **상호 링크** — `우천` 페이지 → 영향받은 `타설` 공종 페이지 → 그 공종 잘하는 **업체 프로파일(B와 결합)** → 실제 사례 카드
4. **휴먼 큐레이션** — PM이 핀/정정/주석 → 위키가 신뢰 가능해지고, 그 정정이 다시 학습 신호가 됨

### 만들어질 수 있는 시나리오
- **① 아침 공정회의가 바뀐다** — "비 왔는데 오늘 타설 강행?" → `우천×타설` 페이지: 과거 12건 중 강행 8건, 평균 회복 D+1.5, 당시 조치 3가지. **감 → 데이터 근거.**
- **② 사람이 바뀌어도 현장이 안 멈춘다** — PM 교체·인원 교대 시 지식 증발(건설 고질병)을 위키가 막음. **인수인계가 페이지 한 장으로.**
- **③ 실수가 반복되지 않는다** — 같은 조건에서 같은 문제 재발 시 "주의: 과거 3회 동일 패턴" 선제 경고. 현장이 *경험에서 학습.*
- **④ 한 현장의 노하우가 다른 현장으로 복제된다** — 잘 굴러간 현장의 위키를 신규 현장 착공 시 **"스타터 위키"로 복제** → 전사 현장 운영 상향평준화.

### "현장의 변화"의 핵심 — 작업일보의 위상이 바뀐다
- 지금 작업일보 = *보고용 산출물* (쓰고 버려짐, 작성은 의무·귀찮음)
- 위키가 생기면 = 작업일보 작성이 **곧 조직 지식에 기여하는 입력**

→ "내가 쓴 일보가 다음 사람을 돕고 내 판단 근거가 된다"는 피드백이 생기면 **일보 작성 동기·품질이 올라가고**, 그게 다시 위키를 두껍게 하는 **선순환**. 이것이 "현장의 변화"의 진짜 시작점.
부차적으로 B와 결합하면 협력사에 "이 조건에 강하다/약하다"를 데이터로 공유 → 협력사 행동 유도.

### 활용 데이터 (A와 동일 + 큐레이션 레이어)
- 페이지 본문 = `daily_activities`(원천) + `forecasts`(결과) + `optimizer_advice`(조치)를 주제 키(공종·조건·구역)로 묶어 LLM 요약
- 신규: **큐레이션 저장소** (핀·정정·주석) — `mapping_corrections`와 같은 "휴먼 피드백 누적" 패턴 재사용 가능

### 구현 가능 범위 (정직한 단계 구분)
| 단계 | 가능 여부 | 비고 |
|------|-----------|------|
| **주제별 자동 요약 페이지 (단일 현장)** | 🔸 부분 가능 | A 검색 결과를 주제 키로 묶어 요약하면 됨. 페이지 "두께"는 누적 의존 |
| **자가 성장 (매일 갱신)** | 🔸 부분 가능 | 일배치로 관련 페이지 재요약. 갱신 트리거 설계 필요 |
| **휴먼 큐레이션 (핀·정정)** | ✅ 패턴 존재 | `mapping_corrections` 식 피드백 누적 재사용 |
| **현장 간 스타터 위키 복제** | ⚠️ 다현장 누적 후 | PoC 1현장에선 개념 증명까지 |

### 정직한 제약
- **신뢰성이 생명** — 자동 요약이 틀리면 위키 전체 신뢰 붕괴. 휴먼 검수 필수. 위키는 *보조*, 최종 판단은 사람(특히 안전 영역).
- **Cold start** — 누적 전엔 페이지가 얇음. PoC 단일 현장에선 위키의 두께가 한계.
- **큐레이션 주체** — 누가 관리하나. 자동 생성 + 가벼운 검수 루프로 부담 최소화 설계 필요.

## B. 업체 인텔리전스 — 조건부 프로파일

### 한 줄 정의
> 같은 업체가 여러 기간·공종·조건에서 보인 실적을 모아 **조건부 프로파일**을 만든다. "남웅건설은 우천 시 생산성 하락폭이 평균보다 작다(우천에 강하다)" 같은 데이터 기반 업체 진단.

### 구성
1. **업체 선택** → 프로파일 화면
2. **조건부 레이더 / 히트맵** — (공종 × 조건) 생산성 지수를 현장 평균 대비로. 어느 조건에 강하고 약한지 한눈에.
3. **회복속도 지표** — degradation 후 며칠 만에 회복했나
4. **공기 성향** — 공종별로 만성 지연인지 / 앞서가는지 (`mh_gap` 누적 부호·크기)
5. **랭킹 테이블** — 공종별 업체 비교

### 활용 데이터
| 지표 | 어디서 | 산식 개념 |
|------|--------|-----------|
| 생산성 지수 | PG `forecasts.today_productivity` | 업체×공종×조건 평균 ÷ 같은 공종 peer 평균 (공종마다 절대값이 달라 정규화 필요) |
| 조건 민감도 | `forecasts.today_conditions` + 생산성 | 조건 X일 때 생산성 ÷ 맑음일 때 생산성 (업체×공종 내) |
| 회복속도 | `optimizer_advice.recovery_distribution` / `recovery_likelihood` | degradation 후 회복까지 일수 집계 |
| 공기 성향 | `forecasts.mh_gap` | 누적 부호·크기 (양수 누적 = 만성 지연) |

### 산출 인사이트
- **발주/입찰 협상력** — "이 공종, A업체 vs B업체 중 과거 실적상 누가 공기 안정적?"
- 조건부 강·약점 카드 ("우천 강함 / 동절기 약함")
- 공종별 신뢰도 랭킹

### 구현 가능 범위 (정직한 단계 구분)
| 단계 | 가능 여부 | 비고 |
|------|-----------|------|
| **단일 업체 생산성·공기 성향** | ✅ 지금 바로 | `forecasts` 시계열만으로 됨 |
| **조건 민감도 프로파일** | 🔸 부분 가능 | `today_conditions` 파싱 필요, 조건별 표본 수가 관건 |
| **업체 간 peer 비교·랭킹** | ⚠️ 데이터 다양성 필요 | **PoC는 실현장 1개 → 공종당 업체 수가 적어 비교 표본 부족** |

### 한계 / 리스크
- **데이터 다양성이 최대 제약** — 조건부 프로파일과 peer 랭킹은 "여러 업체 × 여러 현장 × 여러 조건"이 모여야 의미. PoC 데이터(실현장 1 + synthetic)로는 *구조는 증명하되 결론은 약함.*
- 정직한 포지셔닝: **"아키텍처는 준비됨, 정밀도는 누적과 함께"** — 또는 시연용으로 synthetic을 다업체로 풍부화하면 vivid해짐(별도 판단).

## 종합 — 단계적 확장 그림

```
[지금 바로 — PoC 데이터로 가능]
  A: 칩 필터 + 사례 카드 + 인용 기반 채팅 (단일 현장 내)
  B: 단일 업체 생산성·공기 성향

[데이터 누적/풍부화 후 — 진가 발휘]
  A: 현장 간 지식 전이, 인수인계 자동화
  B: 조건부 프로파일, 업체 간 peer 랭킹, 입찰 의사결정 지원
```

| | A. 현장 기억 | B. 업체 인텔리전스 |
|---|---|---|
| 즉시성 | 높음 (단일 현장 내 바로) | 중간 (단일 업체 지표는 바로, 비교는 누적 후) |
| 핵심 데이터 | `daily_activities`(Chroma) + 조인 | `forecasts` 집계 |
| 데모 임팩트 | 큼 ("물어보면 답한다") | 비전형 (누적될수록 강함) |
| 최대 리스크 | 환각 (인용으로 차단) | 데이터 다양성 부족 |
| CPIA 차별점과의 정합 | "이력 기반 상대 판단"의 검색 버전 | "이력 기반 상대 판단"의 집계 버전 |

> 두 아이디어 모두 CPIA의 핵심 철학 — **"절대 기준(품셈) 없이, 쌓인 현장 실적으로 상대 판단"** — 의 자연스러운 연장선이다. A는 그 기억을 *꺼내 쓰고*, B는 *모아서 비교한다.*

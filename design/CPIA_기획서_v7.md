## 00 — 우리가 처한 상황: Hi-tech 현장 인력 부족

SK에코플랜트 Hi-tech 사업부는 반도체·배터리 공장 EPC 수주가 급증하는 상황에서
**현장 Front Office 역량 인력 확보**라는 과제에 직면해 있습니다.

- Hi-tech EPC 현장 특성상 공정 판단·발주처 협의·리스크 대응이 가능한 **Front Office 인력** 수요 급증 (26년: 1,000명 수준 추가 EPC 인원 확보 필요)
- 그룹 차원에서 ABI(AI Business Innovation) 추진 중 — 워크플로우 재설계와 조직 구조 변화가 핵심 화두
- 현장 인력을 추가로 뽑는 것만으로는 한계: **기존 인력이 Middle Office 업무에 묶여** Front 역할을 못 하고 있음

> 이 과제의 답은 "더 뽑는 것"이 아니라 **"지금 있는 사람을 Front로 돌리는 것"**입니다.
> AI가 Middle Office를 대체하면, 현장 엔지니어는 본연의 판단 업무에 집중할 수 있습니다.

## 01 — 현장 업무 구조 진단: Middle Office가 병목이다

건설 현장에는 수백 개의 협력사가 매일 작업일보를 생성하고, 이를 현장 PM과 발주처가 의사결정에 활용합니다.
그런데 데이터를 만드는 사람과 데이터로 판단하는 사람 사이에,
**데이터를 취합·정리·재작성하는 레이어**가 존재합니다.

```
┌────────────────────────────────────────────────────────────────┐
│  BP / 협력사 (작업일보 생성)                                      │
│       ↓                                                        │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │            MIDDLE OFFICE                                  │  │
│  │  데이터 취합 → 집계 → 검증 → 보고서 작성 → 리스크 모니터링  │  │
│  │                                                           │  │
│  │  ← 지금 현장 엔지니어가 하고 있는 일 ←                      │  │
│  └──────────────────────────────────────────────────────────┘  │
│       ↓                                                        │
│  현장 PM / 경영진 (의사결정)                                      │
└────────────────────────────────────────────────────────────────┘
```

| Layer | 역할 | 건설 현장 예시 |
|-------|------|----------------|
| **Front Office** | 수익 창출·의사결정 | 발주처 협의, 공정 문제 해결, 리스크 판단·실행 |
| **Middle Office** | 데이터 중계·검증·보고 | 작업일보 취합, 보고서 작성, 공기 모니터링 |
| **Back Office** | 기록·정산·시스템 | 기성 정산, 퇴직공제, ERP 관리 |

이 구조에서 핵심 질문은 하나입니다.

> **"Middle Office를 AI로 대체하면, 그 인력을 어디에 쓸 수 있는가?"**

답을 찾기 위해 Hi-tech 사업부 전체 업무를 전수 조사했습니다.

## 04 — 워크플로우 재설계: Middle Office → AI Agent

### AS-IS: 현재 (수작업 7단계, 담당자 전일 투입)

```
① BP 이메일·카카오톡 수동 열람    1~2h/일   100개사+ 개별 확인
② 엑셀 복붙·집계 (수작업)         2~3h/일   인원·물량·장비 수기 합산
③ 이상치 발견 시 업체 유선 확인   1h/일     전화·문자 개별 협의
④ 공정표 항목 수작업 매핑         —         Actual → Plan 수기 대조
⑤ PPT·엑셀 보고서 수기 작성       2h/일     S-Curve·공정률 표·시각화
⑥ 발주처 이메일 수동 발송         —         D+2~3일 지연 발송
⑦ PM 경험칙으로 공정 이상 판단    —         주간 회의 후 인지 → 이미 늦음
```

결과: **담당자 1~3명 전일 투입 | 보고 D+2~3일 지연 | 지연 후 만회 불가**

### TO-BE: AI Agent 도입 이후 (담당자 역할 전환)

```
① 이메일·카카오톡 자동 수집·파싱      Collector Agent  →  0분
② 비정형 일보 → WBS 구조화 JSON     Parser Agent     →  0분
③ 공정표 의미 기반 자동 매핑         Mapper Agent     →  검증 10분  [H-i-L 1]
④ 작업 기록 현장 지식 DB 자동 적재   Atomizer Agent   →  0분
⑤ 통합 보고서 자동 생성·발송         Reporter Agent   →  검토 10분
⑥ 오늘 생산성 현장 이력 대비 진단    Forecaster Agent →  의사결정 집중  [H-i-L 2]
⑦ 과거 유사 패턴 기반 만회 조언      Optimizer Agent  →  PM 최종 판단
───────────────────────────────────────────────────────────────
★ PM: AI 진단 결과 검토 → 발주처 협상 → 현장 조치 (본연의 역할)
```

결과: **검토·승인 30분/일 | D+0 당일 발송 | D-14 선제 대응**

## 05 — CPIA: 우리가 설계한 Answer

### Middle Office를 AI Agent로 교체한다

CPIA는 보고서를 빠르게 만드는 도구가 아닙니다.

> **Middle Office 레이어 자체를 AI Agent로 대체하여,**
> **Front Office(PM·엔지니어)가 AI와 직접 일하는 구조로 전환합니다.**

```
✅ 올바른 프레이밍: "Front가 AI Agent와 직접 일하는 구조로 전환한다"
   → Middle Office 인력 = Agent 오케스트레이터로 업스킬링
   → PM은 데이터를 취합하는 사람에서 데이터로 판단하는 사람으로
   → 조직 차원의 AX 실현
```

### 프레임워크 선택: LangGraph

CPIA는 단순 자동화 스크립트가 아닙니다. 7개 전문 Agent가 순서와 조건에 따라 협력하는 **멀티에이전트 워크플로우**입니다. 이를 위해 **LangGraph**를 채택합니다.

| 비교 항목 | LangChain | **LangGraph** |
|---------|-----------|--------------|
| 구조 | 순차 체인 (A → B → C) | **그래프 State Machine** |
| 멀티에이전트 | 단일 에이전트 권장 | **다수 에이전트 조율 내장** |
| 조건 분기 | 수동 구현 필요 | **Conditional Edge 기본 지원** |
| Human-in-the-Loop | 별도 구현 | **interrupt 체크포인트 내장** |
| 상태 관리 | 없음 | **CPIAState 공유 — 노드 간 데이터 자동 전달** |
| 중단·재개 | 불가 | **Checkpointer로 파이프라인 재개** |
| 병렬 실행 | 불가 | **Send() API로 Reporter·Forecaster 동시 실행** |

> CPIA에서 LangGraph가 결정적인 이유: **담당자 "검토 10분" 단계**가 파이프라인 중간에 2회 존재합니다. LangGraph의 `interrupt_before`는 이 Human-in-the-Loop 지점을 코드 한 줄로 구현하고, 승인 후 중단 지점부터 재개합니다.

### Agent 역할 요약

| Agent | 역할 | 모델 |
|-------|------|------|
| Collector | 파일 드롭 감지, 원시 작업일보 저장 | 규칙 기반 (LLM 불필요) |
| Parser | 비정형 텍스트 → WBS 구조화 JSON | Claude Sonnet 4.6 |
| Mapper | 작업 내용 → 공정표 WBS 의미 기반 매핑 + H-i-L 1 검증 | Claude Sonnet 4.6 |
| Atomizer | 오늘 작업 기록을 현장 지식 Vector DB에 임베딩·적재 | 임베딩 모델 |
| Reporter | Daily·Weekly·Monthly 보고서 자동 생성 (사내 + 발주처용) | Claude Sonnet 4.6 |
| Forecaster | 오늘 생산성을 현장 실적 이력 대비 진단 — 이상 여부·원인 추론 | Claude Opus 4.7 |
| Optimizer | 과거 유사 저하 패턴 검색 → 원인 진단 + 만회 조언 제시 | Claude Opus 4.7 |

### Human-in-the-Loop: 2개 지점

| 구분 | 시점 | 담당자 역할 | 소요 시간 |
|------|------|-----------|---------|
| **H-i-L 1 (Mapper)** | 매핑 검증 | AI가 불확실로 플래그한 항목만 확인·수정. 수정 내역 누적 → 이후 자동 학습 | **10분** |
| **H-i-L 2 (Forecaster)** | 조언 대상 선택 | AI가 탐지한 리스크 공종 중 Optimizer에 조언을 의뢰할 공종 선택 | **5분** |

> **피드백 루프:** H-i-L 1에서 담당자가 수정한 매핑은 `corrections.json`에 누적됩니다.
> 같은 작업 내용이 반복 등장할 때 Mapper가 이를 먼저 참조하여 자동 확정 처리합니다.
> 반복할수록 사람 개입이 줄어드는 자기학습 구조입니다.

### 핵심 차별점: "현장이 스스로 기준을 만든다"

기존 생산성 관리는 외부 표준(품셈, 국가 표준 단가)을 기준으로 현장 실적을 평가했습니다.
CPIA v2는 이 방식을 근본적으로 바꿉니다.

```
[기존 방식]
실측 생산성 ÷ 외부 기준(품셈) = 달성률
→ "오늘 거푸집이 기준의 78%다" → 경고
→ 문제: 기준이 현장 조건(날씨·구역·업체 숙련도)을 반영하지 못함

[CPIA v2 방식]
오늘 실적 vs 과거 유사 상황 (Vector DB 검색)
→ "오늘은 우천이고 병행작업이 있었다. 과거 같은 조건에서 이 업체의 평균은 X였다.
   오늘 실적은 그보다 정상 범위다." 또는 "비정상이고 작업내용에 장비 대기가 기재됐다."
→ 현장 고유 패턴을 학습한 AI가 맥락을 고려한 판단을 한다
```

| 구분 | 외부 기준 방식 | CPIA Vector RAG 방식 |
|------|-------------|---------------------|
| 기준 소스 | 국가 표준 품셈 (외부) | 현장 실적 이력 (내부) |
| 현장 적합도 | 낮음 (이상적 조건 가정) | 높음 (이 현장, 이 업체, 이 조건) |
| 날씨·여건 반영 | 불가 | 가능 (작업내용 텍스트 분석) |
| 정확도 추이 | 고정 | 데이터 누적될수록 향상 |
| AI 판단 근거 | "기준 대비 X%" | "과거 유사 3건에서 이러했고, 오늘은 이 상황이다" |

### 데이터 선순환 구조

```
매일 작업일보 투입
        ↓
Atomizer → Vector DB (현장 지식 자동 누적)
        ↓
Forecaster 판단 정확도 향상 (데이터가 쌓일수록)
        ↓
Optimizer 조언 근거 풍부화 (유사 사례 증가)
        ↓
현장 신뢰 증가 → 데이터 품질 향상 → D-14 탐지 신뢰도 향상 (선순환)
```

## 07 — 데이터 준비도

AI 학습 및 추론에 필요한 3종 데이터가 **이미 확보**되어 있습니다. 별도 인프라 구축 없이 즉시 시작 가능합니다.

| 구분 | 데이터 | 형태 | 준비도 |
|------|--------|------|-------|
| **Plan** | 실행내역서·마스터 공정표·WBS·CBS·Staffing Norm | Excel, P6, CPMS | ✅ 즉시 활용 |
| **Actual** | BP 일일 작업일보 (비정형 텍스트 + Excel 혼합)·타각 기록 | 이메일·카카오·Excel | ✅ 즉시 활용 |
| **Knowledge** | **현장 작업 이력 Vector DB** (Actual 누적 자동 생성) | ChromaDB (로컬) | ✅ **파이프라인이 자동 구축** |

> **v7 핵심 변경:** 외부 지식(품셈·표준단가)에 의존하지 않습니다.
> CPIA가 매일 작업일보를 처리하면서 Atomizer가 자동으로 현장 지식 DB를 구축합니다.
> 현장이 가동될수록 AI의 판단 정확도가 높아지는 구조입니다.
> 초기(데이터 부족 구간)는 WBS 계획값을 fallback으로 사용하며, 누적 실적이 쌓이면 자동 전환됩니다.

> 보안: 실행내역·작업일보 대외비 등급 → 전사 AI 인프라(사내 승인 환경) 사용 전제. 고객 개인정보 미포함으로 규제 리스크 없음.

## 09 — 향후 확장성

Hi-tech 현장 검증 후 사업부 확산, 나아가 외부 수익화까지 동일 구조로 복제 가능합니다.

```
HORIZON 1 (0~6개월)           HORIZON 2 (6~18개월)        HORIZON 3 (18개월+)
Hi-tech 전 현장 검증  ──→     전사 사업부 확산         ──→  AI Solution 상품화

6개 현장 순차 확산             AI Solution 사업부 적용       CPIA SaaS 제품화
발주처 연동 표준화              에너지·배터리 현장 확장         타 건설사 파일럿 영업
경영진 대시보드 오픈            글로벌(Indiana) 영문 지원       발주처 직접 서비스

2,155h/월 절감                 4,200h+/월 절감 추정           외부 수익화
```

> **확장성 핵심:** Vector DB 기반 설계는 현장별 독립 학습이 가능합니다.
> 현장 A의 지식이 현장 B로 오염되지 않으면서도, 동일 공종의 패턴은 선택적으로 공유 가능합니다.
> 현장이 늘어날수록 각 현장의 AI 판단 정확도가 독립적으로 향상됩니다.

```
이 과제는 보고서를 빠르게 만드는 것이 아닙니다.

  현재 구조                        CPIA 이후
  ─────────────────────            ──────────────────────────────────
  엔지니어 = 데이터 취합자  ──→    엔지니어 = 데이터 기반 판단자
  Middle Office 존재        ──→    AI Agent가 Middle Office
  6개 현장 개별 중복 수행   ──→    단일 플랫폼으로 전 현장 처리
  지연 후 사후 대응         ──→    D-14 선행 탐지·만회 실행
  외부 기준(품셈)으로 평가  ──→    현장 실적이 스스로 기준이 됨
```

SK에코플랜트가 추구하는 ABI(AI Business Innovation)의 핵심은
단순 업무 자동화가 아니라 **워크플로우 재설계를 통한 조직 구조 변화**입니다.

CPIA는 그 첫 번째 실증입니다.
Middle Office를 AI로 대체하고, 현장 엔지니어를 데이터 중계자에서 **판단·협상·실행의 주체**로 전환합니다.
이것이 Hi-tech 현장 인력 부족을 새로 뽑지 않고 해결하는 방법입니다.

Hi-tech 현장 공기 지연 1일의 LD 리스크는 수억~수십억 원 규모입니다.
CPIA는 연간 약 203억 원 직접·충원 절감과 함께 그 이상의 리스크를 제거하며,
무엇보다 **Hi-tech 사업부가 일하는 방식 자체를 바꾸는 조직 차원의 AX**입니다.

## 01 — Background · 현장 인력을 실행 중심으로 재배치

이 과제는 단순히 현장의 보고 업무를 줄이는 자동화가 아닙니다.
현장 엔지니어가 수행하는 업무 중 **AI로 대체 가능한 Middle Office 레이어를 제거**하고, 그 인력을 **Front Office 본연의 역할(공정 판단·발주처 협상·리스크 실행)** 로 재배치함으로써 조직의 일하는 방식을 구조적으로 전환합니다.

### Construction Site — 3-Layer Structure

| Layer | 핵심 역할 | 주요 업무 | 상태 |
|-------|---------|---------|------|
| **Front Office** — 현장 관리·커뮤니케이션 | 사람만 가능한 본질적 역할 | 발주처 협의·의사결정 / 공정 문제 해결·현장 조치 / 리스크 판단·Catch-up 실행 / 협력사(BP) 관계 관리 | 현장 인력 부족에 따른 확충 필요 |
| **Middle Office** — 데이터 집계·검증·보고 **★ CPIA 타겟** | AI 로 대체 가능한 레이어 | 작업일보 취합·정합성 검증 / 공정률·생산성 보고서 작성 / 공기 지연 리스크 집계·모니터링 / 회의 자료 데이터 가공·포매팅 | **Hi-tech 2,506h/월 소비** (현장 Activity 전수 조사 기준) |
| **Back Office** — 검토·정산·시스템 | 기존 운영 유지 영역 | 기성 정산·회계 처리 / 퇴직공제 신고·기록 / ERP·PMIS 시스템 관리 / 계약 문서 보관·관리 | 현행 유지 (CPIA 범위 외) |

```
[ 협력사 / 현장관리자 ]  ←  [ ~~현장사무직 / 계약직~~  → AI Agent 로 대체, Front Office 로 이동 ]  →  [ 현장 PM · 본사 ]
       Middle Office 인력 재배치                                                                          의사결정 집중
```

### Reframing — 왜 "없애는 것"이 아닌 "재정립"인가

**Middle Office 인력 = Agent 오케스트레이터** 로 업스킬링하여, Front Office 역할을 더 명확히 하고 조직 구조적 AX 를 실현합니다.

> "없앤다"는 프레이밍은 저항을 부르지만 — **"직접 AI 와 일하는 구조로 전환"** 은 가능성을 엽니다.

## 02 — Process · 수작업 7단계 → 7-Agent 자동화

담당자 1~3명이 전일 매달리던 취합·보고·분석 사이클을 7개 Agent의 업무로 대체하고, 담당자의 역할이 **보고서 작성자** 에서 **의사결정자** 로 전환됩니다.

| # | AS-IS (수작업) | TO-BE (7-Agent / LangGraph) | Core AI |
|---|--------------|----------------------------|:------:|
| 1 | BP 이메일·카톡 수동 열람 (1~2h/일) | **Collector** · 이메일·카톡 자동 수집·파싱 (0분) | |
| 2 | 엑셀 복붙·집계 수작업 (2~3h/일) | **Parser** · 비정형 작업일보 → WBS 구조화 (0분) | |
| 3 | 공정표 항목 수작업 매핑 (1h/일) | **Mapper** · 공정표 의미 기반 자동 매핑 (검증 10분) | ★ |
| 4 | 현장 이력 축적 없이 매번 재취합 (1h/일) | **Atomizer** · 작업 기록 현장 지식 DB 적재 (0분) | |
| 5 | PPT·엑셀 보고서 수기 작성 (2h/일) | **Exporter** · 통합 작업일보 자동 생성·출력 (검토 10분) | |
| 6 | PM 경험칙으로 공정 이상 판단 (D+2~3일 사후 인지) | **Forecaster** · 생산성 현장 이력 대비 진단 | ★ |
| 7 | 공기 만회 대책 사후 임시 수립 (만회 불가 구간 진입 후) | **Optimizer** · Catch-up 시나리오 자동 생성 | ★ |

```
AS-IS                                          TO-BE
담당자 1~3명 전일 투입                ──→     담당자 30분/일 투입
보고 D+2~3일                          ──→     보고 D+0 (당일)
지연 사후 인지                         ──→     공기 위험 D-14 선제 대응
```

## 03 — Core AI · CPIA, 어떻게 사람을 대신하는가

시스템으로는 대체 불가능한 사람이 필요한 판단·해석 영역을 아래 세 가지 CORE AI 가 직접 수행합니다.

### Core AI 01 · Mapper — 작업일보 실적 정보 → WBS 자동 매핑

| Before | After |
|--------|-------|
| 사람 1~3 h / 일 | **AI 10 분 / 일** |

협력사가 작성한 작업 내용의 문맥을 파악하여 의미 기반으로 WBS 에 자동 연결합니다. AI 가 신규 발생 작업에 대해 평균 정확도 **약 92%** 로 매핑하면, 사람은 확신도 낮은 **8%의 작업 건만 검토** 하면 됩니다.

> 예시: "철근 배근 작업 진행 80%" → `IBL-CIV-RC-04` (96%) · "거푸집 해체 완료" → `IBL-CIV-FW-12` (88%) · "현장 정리 및 자재 이송" → 매핑 불가(41%) → **사람 검토**

### Core AI 02 · Forecaster — 오늘의 생산성 Risk 는? AI 가 자동 진단

| Before | After |
|--------|-------|
| D+2~3 일 사후 인지 | **D+0 당일 진단** |

현장의 금일 Productivity 와 Impact 를 기준으로 **4분면(정상·주의·위험)** 으로 진단하여, 현장관리자는 별도 분석 작업 없이 위험 항목에 대해 빠르게 조치하여 현장 공기 단축에 보다 집중하여 수행할 수 있습니다.

```
              Impact (영향도)
                  ▲
            주의  │  위험   ← Optimizer 자동 라우팅
       ───────────┼───────────▶ Productivity (생산성)
            정상  │  주의 (구 관찰)
```

> 예시 진단 결과: **정상 9 · 주의 3 · 위험 2** — 위험 분면의 공종이 다음 Agent (Optimizer) 로 자동 라우팅

### Core AI 03 · Optimizer — 예상 지연 공기와 만회 시나리오 동시 제공

| Before | After |
|--------|-------|
| 사후 대책 수립 | **조기 대응 및 방안 제시** |

생산성을 기반하여 최적화 가능한 공사기간을 제시하고, **과거 작업 패턴을 분석** 하여 유사 만회 시나리오와 Catch-up Plan 을 사전에 제시합니다. 현장관리자는 문제 해결에만 집중하면 됩니다.

> 예시: **RC 공종 — D-14 만회 가능 구간 진입** · 유사 과거 사례 12건 분석
> ① **야간 작업 + 인력 +6명** (RC 4공구 집중 투입) → **-3일** ★ 권장
> ② 선행공정 순서 재배치 (FW → CC 병행) → -2일
> ③ 외주 BP사 추가 계약 (기성 BP-12 검토) → -1일

## 05 — Scalability · 조직의 변화로 이어지는 확장 가능성

현장별 양식엔 노드 교체로 즉시 대응. 동일 Agent 는 모든 사업 프로덕트에 그대로 적용. 시공의 학습은 설계·구매 영역까지 확장되어 EPC value chain 전반의 공기 단축으로 이어집니다.

| Axis | Category | 내용 | Impact |
|------|---------|------|--------|
| **AXIS 01** | **Modular Adaptation** — 현장별 양식이 달라도, 노드 교체로 즉시 적용 | 유지보수가 간편한 LangGraph 기술로 설계하여 현장마다 다른 작업일보 양식에 Parser·Exporter 같은 일부 노드만 교체하면 그 현장에 맞춰 즉시 동작. | **2~3일 내 신속한 커스터마이징 가능** |
| **AXIS 02** | **Cross-Product Reach** — Hi-tech → AI DC · 인프라 · 주택 까지 | 작업일보와 생산성 분석은 현장 종류와 무관한 공통 업무로 Hi-tech 에서 검증한 동일 Agent 를 모든 사업 프로덕트에 그대로 적용. | **전 EPC 사업 프로덕트 공통 적용** |
| **AXIS 03** | **Value Chain Expansion** — MPRS 관점에서의 확장 가능성 | CPIA 는 시공(P) 단계의 최적화를 지향하고 있으나, 누적 데이터·패턴을 설계(R)과 구매/조달(S) 단계로 확장해 예측 가능성을 높이고, 전체 EPC value chain 의 공기 단축 레버 확보. | **PRS 영역의 예상공기 검토시간 50% 절감** |

## 핵심 메시지 — Operational Shift

> **단순 AI 도구 적용이 아닌, 현장 운영 구조의 전환입니다.**
>
> 사람 손을 떠나 작업일보 취합 · 진도 보고 · 만회 계획 수립을 이제는
> 7개의 Agent 가 수행함으로써, 현장을 최적화 해나가고 운영 구조를 변화시키는 첫걸음이 될 것입니다.

```
  현재 구조                        CPIA 이후
  ─────────────────────            ──────────────────────────────────
  엔지니어 = 보고서 작성자  ──→    엔지니어 = 의사결정자
  Middle Office 인력 운영   ──→    AI Agent 가 Middle Office
  6개 현장 개별 중복 수행   ──→    단일 LangGraph 파이프라인 공통 적용
  지연 후 사후 대응         ──→    D-14 선행 탐지 · 만회 조기 착수

```

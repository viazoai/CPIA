서버 CPU 영향

빌드 전후 CPU 비교

next build는 2 vCPU를 90초간 풀가동해 AWS CPU 크레딧을 소진합니다. GitHub Actions runner에서 실행하면 서버는 무관합니다.

이전 — 서버 직접 빌드
docker compose build web
next build (컴파일)~95%
npm ci (패키지 설치)~60%
지속 시간~90초
2 vCPU t-class 인스턴스에서 CPU 크레딧이 소진되어 AWS 버스트 알람 발생.
이후 — GitHub Actions 빌드
workflow_dispatch → docker pull
docker pull (네트워크 IO)~2%
docker compose up~3%
지속 시간~15초
빌드는 GitHub free runner에서 실행. 서버는 이미 완성된 이미지를 받기만 합니다.
자동화 범위

자동 vs 수동 작업

이미지 빌드만 자동화합니다. 스키마 변경처럼 live DB에 직접 접근하는 작업은 의도적으로 수동 유지합니다.

작업 방법 구분
Web 이미지 빌드 · 배포 /build → gh workflow run -f target=web 자동
Pipeline 이미지 빌드 · 배포 /build → gh workflow run -f target=pipeline 자동
PostgreSQL 스키마 변경 docker exec cpia-postgres psql ... < migration.sql 수동
ChromaDB 컬렉션 관리 scripts/ 내 Python 스크립트 직접 실행 수동
PostgreSQL / ChromaDB 재시작 docker compose restart postgres chroma 수동
Synthetic 데이터 재시드 scripts/seed_dummy_year.py 직접 실행 수동
빠른 참조

명령어 치트시트

복사해서 바로 쓸 수 있는 핵심 명령어입니다.

// 빌드 트리거
$
gh workflow run build-web.yml --ref main -f target=all
# 전체 빌드
$
gh workflow run build-web.yml --ref main -f target=web
# 웹만
$
gh workflow run build-web.yml --ref main -f target=pipeline
# 파이프라인만
// 빌드 상태 확인 · 대기
$
gh run list --workflow=build-web.yml --limit=3
# 최근 실행 목록
$
gh run watch <run-id> --interval 10
# 완료 대기
$
gh run view <run-id> --log-failed
# 실패 로그
// 서버 배포
$
docker pull ghcr.io/viazoai/cpia-web:latest
# 이미지 pull
$
docker pull ghcr.io/viazoai/cpia-pipeline:latest
$
docker compose up -d --force-recreate web pipeline
# 재시작
$
docker logs cpia-web --tail 10
# Ready 확인
// 스키마 마이그레이션 (수동)
$
docker exec -i cpia-postgres psql -U cpia -d cpia \ < infra/postgres/migrations/<파일명>.sql
